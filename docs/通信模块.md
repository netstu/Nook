# Nook 通信模块设计与实现

> 为 Nook 添加类 Frida 的远程调试能力

---

## 1. 模块概述

### 1.1 目标

将 Nook 从静态 payload 框架扩展为支持动态脚本加载的远程调试框架，核心能力：

- Host (PC) 远程控制 Device (Android)
- 动态加载/卸载 JavaScript 脚本
- 实时消息传递和 RPC 调用

### 1.2 架构

```
Host (PC)                         Device (Android)
┌─────────────────┐               ┌──────────────────────────────────┐
│  Python SDK     │               │  Nook Server (守护进程)           │
│  / CLI 工具     │◄──── TCP ────►│       │                          │
└─────────────────┘   (ADB fwd)   │       │ Unix Socket              │
                                  │       ▼                          │
                                  │  ┌─────────────────────────────┐ │
                                  │  │ Target Process              │ │
                                  │  │ └── Nook Agent (注入)       │ │
                                  │  └─────────────────────────────┘ │
                                  └──────────────────────────────────┘
```

### 1.3 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 序列化 | 自定义二进制 TLV | 零依赖、高性能、体积小 |
| Host-Server 传输 | TCP | 通过 adb forward 穿透 |
| Server-Agent 传输 | Unix Domain Socket | 本地 IPC 开销低 |
| I/O 模型 | epoll | Android/Linux 标准 |

## 3. 协议设计

### 3.1 帧格式

```
+──────────────+──────────────+──────────────+──────────────────+
│   Length     │     Type     │    MsgId     │     Payload      │
│   4 bytes    │   2 bytes    │   4 bytes    │     N bytes      │
+──────────────+──────────────+──────────────+──────────────────+
     (大端)         (大端)         (大端)         (TLV 编码)

Header = 10 bytes
Length = Payload 的字节数 (不含 Header)
```

### 3.2 消息类型

```cpp
enum class MessageType : uint16_t {
    // 会话管理 (0x01xx)
    kAttachRequest      = 0x0100,
    kAttachResponse     = 0x0101,
    kDetachRequest      = 0x0102,
    kDetachResponse     = 0x0103,
    kSpawnRequest       = 0x0104,
    kSpawnResponse      = 0x0105,
    kResumeRequest      = 0x0106,
    kResumeResponse     = 0x0107,

    // 脚本 (0x02xx)
    kScriptCreate       = 0x0200,
    kScriptCreateResp   = 0x0201,
    kScriptLoad         = 0x0202,
    kScriptLoadResp     = 0x0203,
    kScriptUnload       = 0x0204,
    kScriptUnloadResp   = 0x0205,

    // 消息传递 (0x03xx)
    kScriptMessage      = 0x0300,  // Agent -> Host (console.log, send)
    kScriptPost         = 0x0301,  // Host -> Agent (recv)

    // RPC (0x04xx)
    kRpcRequest         = 0x0400,
    kRpcResponse        = 0x0401,

    // 进程管理 (0x05xx)
    kProcessListReq     = 0x0500,
    kProcessListResp    = 0x0501,
    kAppListReq         = 0x0502,
    kAppListResp        = 0x0503,

    // 控制 (0x06xx)
    kPing               = 0x0600,
    kPong               = 0x0601,
    kError              = 0x06FF,

    // Agent 内部 (0xFFxx)
    kAgentReady         = 0xFF00,
    kAgentShutdown      = 0xFF01,
};
```

### 3.3 TLV 编码

```
┌─────────┬─────────────┬─────────────┐
│  Tag    │   Length    │    Value    │
│ 1 byte  │  2 bytes    │   N bytes   │
└─────────┴─────────────┴─────────────┘

Tag 结构: [FieldId:4bit][Type:4bit]

Type 定义:
  0x1 = uint8
  0x2 = uint16
  0x3 = uint32
  0x4 = uint64
  0x5 = string (UTF-8)
  0x6 = bytes
  0x7 = nested (嵌套 TLV)

示例: Field 1, Type string => Tag = 0x15
```

### 3.4 消息示例

**AttachRequest**
```
Field 1 (pid):        uint32
Field 2 (identifier): string (包名，与 pid 二选一)
```

**AttachResponse**
```
Field 1 (session_id): uint32
Field 2 (pid):        uint32
Field 3 (name):       string
Field 4 (arch):       string ("arm64")
Field 15 (error):     nested {code: int32, message: string}
```

**ScriptMessage**
```
Field 1 (script_id):  uint32
Field 2 (message):    string (JSON)
Field 3 (data):       bytes (可选，二进制数据)
```

```cpp
// Frame - 帧
class Frame {
public:
    static constexpr size_t kHeaderSize = 10;

    Frame(MessageType type, uint32_t msg_id, std::vector<uint8_t> payload);

    MessageType GetType() const;
    uint32_t GetMsgId() const;
    const std::vector<uint8_t>& GetPayload() const;

    // 序列化为字节流
    std::vector<uint8_t> Serialize() const;

    // 从字节流解析
    static bool Parse(const uint8_t* data, size_t len,
                      Frame* out, size_t* consumed);

    // 检查是否需要更多数据
    static bool NeedMoreData(const uint8_t* data, size_t len,
                             size_t* needed);
};

// TLV 编码器
class TlvEncoder {
public:
    void PutUint8(uint8_t field_id, uint8_t value);
    void PutUint16(uint8_t field_id, uint16_t value);
    void PutUint32(uint8_t field_id, uint32_t value);
    void PutUint64(uint8_t field_id, uint64_t value);
    void PutString(uint8_t field_id, const std::string& value);
    void PutBytes(uint8_t field_id, const uint8_t* data, size_t len);
    void PutNested(uint8_t field_id, const TlvEncoder& nested);

    std::vector<uint8_t> Build() const;
};

// TLV 解码器
class TlvDecoder {
public:
    explicit TlvDecoder(const uint8_t* data, size_t len);

    bool GetUint8(uint8_t field_id, uint8_t* out) const;
    bool GetUint32(uint8_t field_id, uint32_t* out) const;
    bool GetString(uint8_t field_id, std::string* out) const;
    bool GetBytes(uint8_t field_id, std::vector<uint8_t>* out) const;
    bool GetNested(uint8_t field_id, TlvDecoder* out) const;
};
```

```cpp
class IoLoop {
public:
    using EventCallback = std::function<void(int fd, uint32_t events)>;

    IoLoop();
    ~IoLoop();

    bool Start();
    void Stop();

    // 添加/移除监听
    bool AddWatch(int fd, uint32_t events, EventCallback callback);
    bool ModifyWatch(int fd, uint32_t events);
    bool RemoveWatch(int fd);

    // 投递任务到 I/O 线程
    void Post(std::function<void()> task);

private:
    void Loop();

    int epoll_fd_ = -1;
    std::atomic<bool> running_{false};
    std::thread loop_thread_;
    std::unordered_map<int, EventCallback> watches_;
};
```

```cpp
    host_listener.Listen();
```
